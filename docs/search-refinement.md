# Controlled search and training refinement

Updated 2026-10-11. Changes are tested individually against an immutable copy
of the released 96-channel model. Increasing network width previously failed
the [release gate](wide-run.md), so this campaign first checks search and
training-data changes. The live opponent remains the released model until a
candidate passes its recorded evaluation gate.

## Exact tactical diagnostics

Each suite contains 48 reachable positions generated by random legal prefixes,
plus eight shared chain and loop fixtures. Randomized positions cover 3×3, 4×4,
5×5 and 2×5 boards with 12, 14 or 16 remaining edges. The structured fixtures
include unopened chains, loops and positions requiring control handouts. Exact
minimax supplies the final box margin after each legal action.

Outcome accuracy asks whether the selected action preserves the best possible
win, draw or loss. Margin accuracy additionally requires the largest final box
margin. A forced loss can therefore be outcome-correct; the two metrics answer
different questions. Search value error compares the backed-up root value with
the exact outcome, rather than measuring the network's raw value prediction.

Both variants use 128 fresh simulations and a root solver at 12 remaining
edges, matching the current UI's endgame assistance. The candidate also replaces
neural leaf estimates with exact outcomes at 12 remaining edges. The network
and every other search setting are fixed.

| Suite | Search | Outcome correct | Best margin | Mean regret, boxes | Root value MAE |
| --- | --- | --- | --- | --- | --- |
| Tuning, seed 3100 | Root solver only | 55/56 | 53/56 | 0.250 | 0.164 |
| Tuning, seed 3100 | Exact leaves too | 56/56 | 53/56 | 0.107 | 0.137 |
| Fresh random seed 3101 | Root solver only | 55/56 | 53/56 | 0.143 | 0.168 |
| Fresh random seed 3101 | Exact leaves too | 55/56 | 54/56 | 0.071 | 0.112 |

The eight fixtures are shared, so only 48 positions in the second suite are
independent of the first suite. Sixteen positions in each suite are already
covered by the baseline's root solver. These are small late-game diagnostics;
high accuracy does not establish sound opening or midgame play. The tuning
outcome improvement did not recur on the fresh random seed.

On the fresh suite, the compiled development backend took 3.93 seconds for the
baseline and 1.68 seconds for exact leaves. A separate matched NumPy-only run,
with Python search and solving, took 4.42 and 11.34 seconds respectively.
Optional compilation changes the cost substantially. These single-run timings
were collected on a shared machine and are not isolated speed benchmarks.

## Experiment 1: exact search leaves

The [plan](data/search-refinement-20261011/leaf-evaluation-plan.json) was saved
before matches. Both players use the same checkpoint, root solver and fresh
simulation count. Only the candidate's leaf solver changes. Two seeds, 3120
and 3121, each supply 40 games per board and budget, with balanced seats and
six random opening moves. Both players run in the NumPy-only deployment
environment with optional Cython extensions absent. Score gives draws half a
point. Latency excludes UI animations and deliberate move delays.

| Thinking | Board | Wins–draws–losses | Score | Candidate/opponent mean seconds per move |
| --- | --- | --- | --- | --- |
| Standard, 128 | 4×4 | 37–9–34 | 51.875% | 0.076 / 0.063 |
| Standard, 128 | 5×5 | 31–0–49 | 38.750% | 0.105 / 0.093 |
| Deep, 512 | 4×4 | 40–12–28 | 57.500% | 0.211 / 0.183 |
| Deep, 512 | 5×5 | 42–0–38 | 52.500% | 0.317 / 0.303 |

**Decision: reject enabling exact leaves globally.** The recorded gate requires
at least 50% score on both boards at both budgets, strictly above 50% on 5×5
Deep, and mean move latency within twice the opponent's. Standard 5×5 fails.
The small Deep gain is an observation, not proof of superiority or evidence
for changing that setting without another fresh comparison. A better tactical
fixture score did not predict a universal full-game improvement.

## Experiment 2: tree reuse

**Status: complete; deployment gate failed.** [Recorded plan](data/search-refinement-20261011/tree-evaluation-plan.json).
Seeds 3130 and 3131 repeat the same four board/budget combinations. Exact leaf
solving stays disabled for both players. The candidate retains visited
descendants across moves while both players still receive the same number of
fresh simulations. Receipts measure inherited visits and move latency.

| Thinking | Board | Wins–draws–losses | Score | Mean move seconds, candidate/opponent | Mean inherited visits |
| --- | --- | --- | --- | --- | --- |
| 128 | 4×4 | 27–10–43 | 40.000% | 0.069 / 0.057 | 20.2 |
| 128 | 5×5 | 42–0–38 | 52.500% | 0.102 / 0.092 | 37.4 |
| 512 | 4×4 | 39–8–33 | 53.750% | 0.195 / 0.187 | 95.9 |
| 512 | 5×5 | 37–0–43 | 46.250% | 0.337 / 0.307 | 159.2 |

**Decision: retain fresh-tree search as the default.** Standard 4×4 and Deep
5×5 fail the recorded gate. Inherited work is measurable, but it did not produce
a consistent playing-strength gain. More search or memory reuse need not improve
results with a learned leaf evaluator. These matches test behavior rather than
prove why the regression occurs.

Reuse is optional and defaults to false. Tests cover changes of board, undo,
independent batched games, weight updates and removal of exploration noise
before evaluation. Exact game-rule values can survive weight updates; learned
predictions and accumulated tree visits cannot.

## Subsequent training comparisons

The [training guide](training.md#controlled-refinement-options) documents three
matching presets: control, fewer replay updates, then midgame starts. Each arm
starts from the same immutable released checkpoint, with 96 channels, six
layers, 8,192-position batches, 512 search simulations and a root-only 12-edge
solver. Four GPU samplers collect 128 games per round. Control uses 16 learner
updates; the ratio arm uses four. The midgame arm retains four updates and starts
half its games from archived self-play positions with 12–28 edges already drawn.

Each arm stops after 64 rounds or two hours, whichever comes first. Compare
equal-round snapshots if completed round counts differ. The learner allocation
cap is 40 GiB, reserving room for samplers, CUDA contexts and the unrelated job
already using about 67 GiB on the shared H200. Allocator caps do not reserve
VRAM or bound all context allocations.

**Status: queued in the sequential controller after tree-reuse matches.**
[Training plan and progress](refinement-training.md) describe the next phases. The midgame
implementation passed an actual two-worker RLlib smoke run: two games,
18 new positions, two midgame starts, six initially drawn edges in total and
eight learner sample presentations. This verifies execution, not improvement.
The complete software suite passed 88 tests.
